# Plan: Google Drive OAuth Adapter and InitiateCloudConnection Use Case

## Goal

Implement the Google Drive OAuth adapter (Task T-4.01-03) and the `InitiateCloudConnection` use case (Task T-4.01-05) to enable the conversational onboarding flow where a user can authorize Google Drive access directly from Telegram/WhatsApp. Task T-4.01-04 (OneDrive adapter) is intentionally skipped for the MVP; selecting OneDrive will return a friendly "coming soon" message instead.

## Context

- `OAuthServicePort` and OAuth domain errors are already defined in `src/domain/ports/oauth.ts` and `src/domain/errors/` (T-4.01-01 completed).
- `DrizzleOAuthTokenRepository` with AES-256-GCM encryption is already implemented (T-4.01-02 completed).
- The message processing pipeline (`src/interfaces/workers/message.worker.ts`) currently has a placeholder for all `ONBOARDING_*` states that only sends a generic "please follow instructions" message.
- BullMQ + Redis are fully wired in `src/main.ts` with existing queues (`process-message`, `incoming-message`, `session-timeout`).
- `googleapis` is present in `package.json` but `google-auth-library` is not; the adapter will use direct `fetch` calls to Google OAuth endpoints.
- The `OAuthServicePort.buildAuthUrl` signature must be updated to accept a `state` parameter so the use case can store the exact CSRF value in Redis.
- Relevant documentation:
  - `docs/adr/adr.md` — ADR-004 (Adapter Pattern), ADR-005 (BullMQ pipeline), ADR-007 (AES-256 token encryption).
  - `docs/features/conversation-state-management.md` — FSM states and `TransitionConversationState` usage.
  - `docs/plans/plan-conventions.md` — plan structure and conventions.
  - `docs/architecture/data-model.md` — `oauth_tokens` schema and indexes.

## Phases

### Phase 1: Google Drive OAuth Adapter and Environment Variables

**Description:**
Add the Google-specific environment variables to the config schema, implement the `GoogleDriveOAuthAdapter` in the Infrastructure layer, and update the `OAuthServicePort` interface so `buildAuthUrl` receives the CSRF `state` generated by the use case.

**Public contracts created / modified:**

- **Env schema:** `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` added to `src/config/env.schema.ts` and `.env.example`.
- **Application services:** `OAuthServicePort.buildAuthUrl` signature changes from `(provider, userId, redirectUri)` to `(provider, state, redirectUri)`.
- **Application services:** `GoogleDriveOAuthAdapter` class created in `src/infrastructure/adapters/oauth/GoogleDriveOAuthAdapter.ts`.
  - `buildAuthUrl` generates a Google OAuth2 URL with `state`, `redirect_uri`, and Drive scope (`https://www.googleapis.com/auth/drive.readonly`).
  - `exchangeCode` performs `fetch` to `https://oauth2.googleapis.com/token`, validates the response, and maps Google errors to domain errors (`OAuthDeniedError`, `OAuthNetworkError`, `OAuthStateMismatchError`).
  - `refreshToken` method implemented (public but not on the interface yet, for future use).
- **Test suites:** `src/infrastructure/adapters/oauth/GoogleDriveOAuthAdapter.spec.ts` — mocks `fetch` for happy path, denied access, network failure, and invalid JSON responses.

### Phase 2: InitiateCloudConnection Use Case

**Description:**
Implement the Application use case that handles provider selection during `ONBOARDING_START`, generates the OAuth URL, stores CSRF state in Redis, schedules a BullMQ reminder job, sends the auth link to the user, and transitions the conversation state to `ONBOARDING_DRIVE`.

**Public contracts created / modified:**

- **Application services:** `InitiateCloudConnectionUseCase` created in `src/application/use-cases/spreadsheet/InitiateCloudConnection.ts`.
  - Input: `{ userId: string; rawMessage: string; externalId: string; channel: 'telegram' | 'whatsapp' }`
  - Output: `{ nextState: FsmState; message: string; payload?: Record<string, unknown> }`
- **Text copies (user-facing):**
  - Provider selection prompt: "¿Dónde tenés tu planilla?\n1. Google Drive\n2. OneDrive"
  - Invalid input re-prompt: "No entendí. Escribí _1_ para Google Drive o _2_ para OneDrive."
  - OneDrive coming-soon message: "OneDrive está en camino 🚧. Escribí _1_ para usar Google Drive por ahora."
  - Auth link message: "Hacé clic en este enlace para autorizar a Gastto: {authUrl}\nTenés 10 minutos."
- **Database schemas:** No DB schema changes.
- **Test suites:** `src/application/use-cases/spreadsheet/InitiateCloudConnection.spec.ts` — mocks `OAuthServicePort`, `TransitionConversationState`, `MessagingOutputPort`, Redis (`setex`), and BullMQ `Queue.add`.

**To-do actions:**

- [x] Create `src/application/use-cases/spreadsheet/InitiateCloudConnection.ts` with:
  - Provider parsing logic that accepts "1", "2", "Google Drive", "OneDrive", and case/space variants.
  - OneDrive selection returns the coming-soon message without changing state.
  - Invalid input returns the re-prompt without changing state.
  - Valid Google selection generates a cryptographically random `state`, calls `OAuthServicePort.buildAuthUrl('google', state, redirectUri)`.
  - Stores `oauth:state:{state}` in Redis with 15-minute TTL, value: JSON of `{ userId, provider, externalId, channel }`.
  - Schedules a BullMQ job on the `oauth-reminder` queue with a 10-minute delay, job ID stored in Redis alongside the state for future cancellation.
  - Sends the auth link via `MessagingOutputPort.sendMessage()`.
  - Transitions state to `ONBOARDING_DRIVE` via `TransitionConversationState.execute()`.
  - Returns the DTO with `nextState`, `message`, and `payload: { provider, state }`.
- [x] Create `src/application/use-cases/spreadsheet/InitiateCloudConnection.spec.ts` with tests for:
  - Valid Google Drive selection → auth link sent, state stored, reminder scheduled, FSM transitioned.
  - OneDrive selection → coming-soon message, no state change.
  - Invalid input → re-prompt, no side effects.
  - Missing/empty message → re-prompt.
- [x] Run `pnpm lint` and `pnpm typecheck` to verify linting and typechecking. Fix issues if any.
- [x] Proceed directly with the next phase.
