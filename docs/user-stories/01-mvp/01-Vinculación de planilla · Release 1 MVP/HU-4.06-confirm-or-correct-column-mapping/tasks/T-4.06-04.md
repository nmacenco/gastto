### Task T-4.06-04: Implement natural-language correction parser

- **Description:** Implement the parser that extracts a mapping correction from a free-text user message, e.g., "no, the category is in column E". The parser identifies the target field (category, amount, date, etc.) and the new column reference (letter, number, or header name). Keep the parser as a domain service or application service with no external dependencies.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] Parser accepts a string and returns either a structured correction `{ field, column }` or a parse failure.
  - [ ] Supports common Spanish/English synonyms and column references (A, B, column E, columna F, etc.).
  - [ ] Returns explicit error when the message does not contain a recognizable correction.

- **Technical dependencies (block the start):** T-4.06-01
- **Delivery dependencies (block the merge):** T-4.06-05

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** Start with a deterministic regex/rules-based parser. If complexity grows, isolate it behind a `CorrectionParser` interface so an LLM-based adapter can replace it later without touching the use case.
