### Task T-4.03-03: Create DrizzleSpreadsheetConfigRepository

- **Description:** Implement the `ISpreadsheetConfigRepository` interface in the Infrastructure layer using Drizzle ORM. This repository must support `findByUserId`, `create`, and `updateAccessVerified`. The `create` method is critical because HU-4.03 is the first point where the `spreadsheet_configs` record can be persisted (fileId and fileName are already known from HU-4.02; sheetName is selected in this HU). Following Option A (per schema decision), `accessVerifiedAt` is initialized to `new Date()` as a placeholder and will be updated to the real timestamp in HU-4.04.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] `DrizzleSpreadsheetConfigRepository` created in `src/infrastructure/db/repositories/DrizzleSpreadsheetConfigRepository.ts`.
  - [ ] Implements `ISpreadsheetConfigRepository` from `src/domain/ports/repositories.ts`.
  - [ ] `findByUserId` queries the `spreadsheet_configs` table by `userId` and returns a `SpreadsheetConfig` domain entity or `null`.
  - [ ] `create` inserts a row with `userId`, `provider`, `fileId`, `fileName`, `sheetName`, and `accessVerifiedAt` (placeholder), and returns the created `SpreadsheetConfig`.
  - [ ] `updateAccessVerified` updates the `access_verified_at` timestamp for a given `id`.
  - [ ] Unit tests with an in-memory Drizzle/test database pass.
  - [ ] `docs/architecture/data-model.md` is updated to reflect the Option A convention (placeholder `accessVerifiedAt` on first creation, real validation in HU-4.04).

- **Delivery dependencies (block the merge):** T-4.03-04
