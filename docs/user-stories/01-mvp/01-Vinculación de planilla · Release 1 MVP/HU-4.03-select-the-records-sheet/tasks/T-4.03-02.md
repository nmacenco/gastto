### Task T-4.03-02: Implement GoogleSheetsAdapter with listSheets and getHeaders

- **Description:** Implement the `GoogleSheetsAdapter` in the Infrastructure layer that satisfies the extended `SpreadsheetPort` for Google Sheets. Use direct `fetch` calls to Google Sheets API v4 (no `googleapis` SDK). The `listSheets` method queries the spreadsheet metadata endpoint to retrieve all sheet names and their indices. The `getHeaders` method reads the first row of a given sheet. The adapter must map responses to the Domain `SheetInfo` and `string[]` types.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [x] `GoogleSheetsAdapter` created in `src/infrastructure/adapters/sheets/GoogleSheetsAdapter.ts`.
  - [x] `listSheets` calls `https://sheets.googleapis.com/v4/spreadsheets/{fileId}` with `fields=sheets.properties(title,index)` and maps to `SheetInfo[]`.
  - [x] `getHeaders` calls `https://sheets.googleapis.com/v4/spreadsheets/{fileId}/values/{sheetName}!1:1` and returns `string[]`.
  - [x] Errors are mapped to `SpreadsheetError` or a new `SheetDiscoveryError` following the existing `FileDiscoveryError` pattern.
  - [x] Unit tests with mocked `fetch` pass.
  - [x] OneDrive adapter is out of scope for MVP; unimplemented methods throw `SpreadsheetError` (placeholder acceptable since T-4.03-04 is not yet merged).

- **Technical dependencies (block the start):** T-4.03-01
- **Delivery dependencies (block the merge):** T-4.03-04, T-4.03-07

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** Keep the same lightweight `fetch`-based approach used in `GoogleDriveFileDiscoveryAdapter`. OAuth `accessToken` is passed as a Bearer token via the `Authorization` header. The adapter is currently missing from the codebase; this is foundational scaffolding for all subsequent spreadsheet operations.
