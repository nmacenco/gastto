### Task T-4.03-06: Integrate sheet selection into message worker

- **Description:** Wire the `HandleSheetSelection` use case into the `message.worker.ts` Interfaces-layer worker. In the `ONBOARDING_SHEET` branch, the worker must instantiate or receive `HandleSheetSelection` (via DI container), pass the `userId`, `rawMessage`, `externalId`, `channel`, and `statePayload`, and send the resulting message back to the user via the `MessagingOutputPort`. The worker must **not** contain business logic; it only deserializes the job payload, retrieves the conversation state, and delegates.

- **Architectural layer:** `Interfaces`

- **Acceptance criteria:**
  - [x] The `ONBOARDING_SHEET` case in `message.worker.ts` is updated to call `handleSheetSelection.execute(...)` instead of sending the placeholder `onboardingCopies.onboardingPlaceholder()`.
  - [x] The `MessageWorkerDeps` interface is updated to include `handleSheetSelection?: HandleSheetSelection | null`.
  - [x] The dependency is injected in the worker creation function (likely in `src/main.ts` or the DI wiring file).
  - [x] If `handleSheetSelection` is not provided (e.g., local dev without the adapter), the placeholder message remains as a fallback.
  - [x] The worker's FSM routing switch covers `ONBOARDING_SHEET` explicitly.
  - [x] Integration tests or manual verification confirm that the worker delegates correctly.

- **Technical dependencies (block the start):** T-4.03-04, T-4.03-05
- **Delivery dependencies (block the merge):** T-4.03-07

- **Estimation:** 0.5 hours

- **Suggested role:** Backend

- **Technical notes:** The `message.worker.ts` already has a pattern for `HandleSpreadsheetFileSelection` (optional injection + fallback). Replicate that pattern for `HandleSheetSelection`. The worker concurrency limit (2) from ADR-005 does not need modification.
