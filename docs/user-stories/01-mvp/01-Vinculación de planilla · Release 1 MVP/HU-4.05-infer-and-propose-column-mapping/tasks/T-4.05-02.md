### Task T-4.05-02: Implement column header inference engine

- **Description:** Implement a rule-based column inference adapter that implements `ColumnInferencePort`. The engine must: (1) normalize headers (lowercase, trim, NFD unaccent, collapse whitespace), (2) match normalized headers against multi-language dictionaries (ES/EN/PT) mapping synonyms to `GasttoField` values, (3) use Levenshtein distance for fuzzy matching when exact match fails, (4) score confidence (`'alta'` for exact/synonym match, `'baja'` for fuzzy match), (5) detect no-header condition using heuristics (row 1 values are all numeric/date, or no string labels found), and (6) validate column content types by inspecting sample rows (e.g., date patterns, numeric patterns) to boost or reduce confidence. The engine must NOT import from Application or Interfaces layers.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] Exact header match returns `confidence: 'alta'` for all 6 `GasttoField` values.
  - [ ] Synonym match (e.g., "Fecha" → `fecha`, "Date" → `fecha`, "Data" → `fecha`) returns `confidence: 'alta'`.
  - [ ] Fuzzy match (e.g., "Fehca" → `fecha` with Levenshtein ≤ threshold) returns `confidence: 'baja'`.
  - [ ] No-header detection: when row 1 values are all numeric/date, `noHeaderFound` is `true`.
  - [ ] Multi-language: ES ("Fecha", "Monto", "Categoría"), EN ("Date", "Amount", "Category"), PT ("Data", "Valor", "Categoria") all resolve correctly.
  - [ ] Unmapped fields are reported in `unmappedFields` when no column matches.
  - [ ] Content-type validation: a column with date-like values in sample rows increases date mapping confidence.
  - [ ] No imports from Application or Interfaces layers.
  - [ ] Unit tests cover all 5 Gherkin scenarios from the User Story.

- **Technical dependencies (block the start):** T-4.05-01
- **Delivery dependencies (block the merge):** T-4.05-05

- **Estimation:** 5 hours

- **Suggested role:** Backend

- **Technical notes:**
  - Implement Levenshtein distance inline (~30 lines) to avoid adding a dependency.
  - Dictionary structure: `Record<string, GasttoField>` with all known synonyms per language.
  - Normalize once, then compare against normalized dictionary keys.
  - Content-type heuristics: regex patterns for dates (`\d{1,2}/\d{1,2}/\d{2,4}`), numbers (`^\d+([.,]\d+)?$`), currency symbols.
  - Confidence threshold for fuzzy match: Levenshtein ratio ≥ 0.75.
  - Reference existing adapter patterns in `src/infrastructure/adapters/sheets/`.
  - Run `pnpm test` after implementation.
