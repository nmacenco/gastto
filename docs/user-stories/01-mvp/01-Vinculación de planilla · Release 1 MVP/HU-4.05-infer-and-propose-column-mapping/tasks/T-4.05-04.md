### Task T-4.05-04: Persist spreadsheet preview in ONBOARDING_MAPPING payload

- **Description:** Update the `ValidateSpreadsheetAccess` use case to include the serialized `SpreadsheetPreview` in the FSM state payload when transitioning to `ONBOARDING_MAPPING` on success. Currently, the success case (line 109–122 of `ValidateSpreadsheetAccess.ts`) stores only `selectedFileId`, `selectedFileName`, `selectedSheetName`, and `provider` in the payload. The `SpreadsheetPreview` is already available from the `SpreadsheetAccessResult` (kind `'success'`) but is discarded. This change stores it so that `InferColumnMapping` (T-4.05-05) can extract headers and sample rows without re-reading the sheet. Update existing tests in `ValidateSpreadsheetAccess.spec.ts` and the feature doc `docs/features/validate-spreadsheet-access.md`.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] On success, the `payload` passed to `transitionState.execute` includes a `preview` key with the serialized `SpreadsheetPreview` (rows, provider, fileId, sheetName).
  - [ ] The `preview` is serializable to JSON (compatible with `jsonb` column).
  - [ ] Existing behavior is unchanged: no message sent, state transitions to `ONBOARDING_MAPPING`.
  - [ ] Existing tests are updated to assert `preview` is included in the payload.
  - [ ] `docs/features/validate-spreadsheet-access.md` is updated to document the preview storage.
  - [ ] All existing `ValidateSpreadsheetAccess` tests still pass.

- **Technical dependencies (block the start):** None
- **Delivery dependencies (block the merge):** T-4.05-05

- **Estimation:** 1 hour

- **Suggested role:** Backend

- **Technical notes:**
  - This is a small, backward-compatible change to HU-4.04.
  - The `SpreadsheetPreview` entity is already defined in `src/domain/entities/SpreadsheetPreview.ts`.
  - The `SpreadsheetAccessResult` already carries the preview on `kind: 'success'`.
  - Serialize the preview as a plain object (the `SpreadsheetPreview` class is frozen but its properties are plain).
  - No DB migration needed — `state_payload` is `jsonb` and accepts any JSON.
  - Run `pnpm test` after changes.
