### Task T-4.01-06: Implement HandleOAuthCallback use case

- **Description:** Implement the Application use case that receives the OAuth callback (code + state), validates the CSRF state, exchanges the code for tokens, persists the encrypted tokens, and sends a success confirmation to the user.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] `HandleOAuthCallbackUseCase` created in `src/application/use-cases/spreadsheet/HandleOAuthCallback.ts`
  - [ ] Validates `state` against Redis; rejects with `OAuthStateMismatchError` if missing or mismatched
  - [ ] Calls `OAuthServicePort.exchangeCode()` to obtain tokens
  - [ ] Persists tokens via `IOAuthTokenRepository.upsert()`
  - [ ] Deletes the temporary OAuth state from Redis
  - [ ] Sends confirmation message via `MessagingOutputPort` ("✅ Google Drive connected successfully" or OneDrive variant)
  - [ ] Cancels the pending reminder BullMQ job if it exists
  - [ ] Returns DTO with `nextState: 'ONBOARDING_FILE'` and `success: true`
  - [ ] On any domain error, returns `success: false`, `errorMessage` (simple language), and `canRetry: true`
  - [ ] Unit tests with mocked ports pass

- **Technical dependencies (block the start):** T-4.01-01, T-4.01-02, T-4.01-03, T-4.01-04
- **Delivery dependencies (block the merge):** T-4.01-08

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:**
  - Clean Architecture boundary: the Fastify route handler (Interfaces) only deserializes query params, validates with Zod, and delegates to this use case. All business logic (state validation, token exchange, persistence, messaging) lives here.
  - BullMQ job cancellation requires the job ID to be stored alongside the OAuth state in Redis.
