### Task T-4.01-03: Implement Google Drive OAuth adapter

- **Description:** Create the Google Drive adapter that implements `OAuthServicePort`. Handle the full OAuth2 authorization-code flow for Google, including token exchange and error mapping.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [x] `GoogleDriveOAuthAdapter` created in `src/infrastructure/adapters/oauth/GoogleDriveOAuthAdapter.ts`
  - [x] Implements `OAuthServicePort`
  - [x] `buildAuthUrl` generates a valid Google OAuth2 URL with `state` parameter, `redirect_uri`, and required Drive scopes
  - [x] `exchangeCode` exchanges authorization code for access/refresh tokens and maps Google errors to domain errors
  - [x] `refreshToken` method implemented (optional but recommended for future use)
  - [x] Unit tests mock the Google Identity endpoint

- **Technical dependencies (block the start):** T-4.01-01
- **Delivery dependencies (block the merge):** T-4.01-06

- **Estimation:** 3 hours

- **Suggested role:** Backend

- **Technical notes:** Use `google-auth-library` if already in `package.json`, otherwise use direct `fetch` to `https://oauth2.googleapis.com/token`. Required scope: `https://www.googleapis.com/auth/drive.readonly` or `drive.file` depending on write needs (check ADR-004). Client ID and secret must be read from environment variables.
