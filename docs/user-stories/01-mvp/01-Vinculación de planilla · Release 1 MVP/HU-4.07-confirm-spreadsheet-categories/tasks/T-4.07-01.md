### Task T-4.07-01: Define domain model for category vocabulary

- **Description:** Create or refine domain value objects/entities that represent a category vocabulary for a user/spreadsheet. Include the category name, an optional display label, an order/index, and a state marker indicating whether the vocabulary is being detected, confirmed, edited, or finalized. Define the default suggested category set as an immutable constant so the empty-column case can use it without infrastructure coupling.

- **Architectural layer:** `Domain`

- **Acceptance criteria:**
  - [x] Value object/entity exists for `CategoryVocabulary` and `Category`.
  - [x] Vocabulary tracks categories, current state (detecting, confirming, editing, confirmed), and the source (detected, default, user-edited).
  - [x] Default category set constant is available for the empty-column scenario.
  - [x] No dependency on Redis, Telegram, LLM, or spreadsheet adapters in the Domain layer.

- **Technical dependencies (block the start):** None
- **Delivery dependencies (block the merge):** T-4.07-02, T-4.07-04

- **Estimation:** 1 hour

- **Suggested role:** Backend

- **Technical notes:** Place under `src/domain/value-objects/` or `src/domain/entities/` following existing project conventions. Refer to HU-4.06 output for the confirmed column mapping structure that identifies the category column.
