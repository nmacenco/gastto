### Task T-4.07-06: Implement confirm categories use case

- **Description:** Implement the application use case that handles the user's confirmation ("yes" or equivalent). It loads the current vocabulary, marks it as confirmed, persists it, signals onboarding completion via the onboarding port, and returns the final welcome message. If no vocabulary exists for the session, it returns a prompt to restart the category detection step.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] Use case accepts user/session identifier and confirmation intent.
  - [x] On confirmation, marks the vocabulary as `confirmed` and persists it.
  - [x] Triggers onboarding completion so Epic 1 can use the persisted vocabulary.
  - [x] Returns the final welcome message text.
  - [x] On missing vocabulary, returns a recovery prompt instead of failing silently.

- **Technical dependencies (block the start):** T-4.07-02, T-4.07-05
- **Delivery dependencies (block the merge):** T-4.07-09

- **Estimation:** 1 hour

- **Suggested role:** Backend

- **Technical notes:** Reuse the onboarding completion port defined in earlier HUs if available. Keep the welcome message content close to the use case or in a domain constant so it can be reused by other interfaces later.
