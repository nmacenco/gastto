### Task T-4.07-06: Implement add and correct categories via natural language use case

- **Description:** Build the Application-layer use case that interprets natural-language instructions to add missing categories or rename existing ones in the user's vocabulary. The use case must parse the intent (add vs. correct), update the `CategoryVocabulary` aggregate accordingly, persist the changes, and return the updated list for re-confirmation. This is the most complex business-logic task of the HU.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] Use case accepts `userId` and a natural-language instruction string.
  - [ ] It correctly identifies "add" intents (e.g., "falta Salud", "add Education").
  - [ ] It correctly identifies "rename" intents (e.g., "Ocio se llama Entretenimiento").
  - [ ] It updates the vocabulary aggregate and persists changes.
  - [ ] It returns an updated presentation DTO with the new category list.
  - [ ] Unit tests cover at least 6 distinct natural-language variations in Spanish and English.

- **Technical dependencies (block the start):** T-4.07-04
- **Delivery dependencies (block the merge):** T-4.07-07

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** This use case contains **all** business logic for intent parsing and vocabulary mutation. The route handler (Interfaces layer) **only** forwards the raw text; no parsing happens there. Consider using a lightweight LLM call via the existing LLM adapter for intent extraction, or a rule-based parser if the scope is narrow. If using the LLM, define an output port in the Application layer so the use case remains agnostic of the LLM provider. Keep the logic testable by mocking the parser/LLM port.
