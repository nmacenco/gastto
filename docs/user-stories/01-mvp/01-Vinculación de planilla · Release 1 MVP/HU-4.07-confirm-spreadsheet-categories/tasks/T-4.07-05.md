### Task T-4.07-05: Implement confirm categories use case

- **Description:** Create the Application-layer use case that handles the user's confirmation of the presented category vocabulary. When the user replies "yes" or an equivalent affirmative, the use case marks the vocabulary as confirmed, completes the onboarding state, and returns the final welcome message payload. No changes are made to the vocabulary itself on confirmation.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] Use case accepts `userId` and a confirmation intent flag.
  - [ ] It marks the user's category vocabulary as confirmed in the repository.
  - [ ] It transitions the user's onboarding status to "completed".
  - [ ] It returns a DTO containing the final welcome message text.
  - [ ] Unit tests verify that confirmation is idempotent (re-confirming does not error).

- **Technical dependencies (block the start):** T-4.07-04
- **Delivery dependencies (block the merge):** T-4.07-07

- **Estimation:** 1 hour

- **Suggested role:** Backend

- **Technical notes:** All business logic (state transition, confirmation flag) lives in this use case. The Interfaces layer handler **only** parses the incoming natural-language confirmation, maps it to the intent flag, and delegates here. Use the existing user/onboarding repository or create an output port if one does not exist. Log the transition with the Pino logger injected via constructor DI.
