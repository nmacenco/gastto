### Task T-4.07-05: Implement detect and present categories use case

- **Description:** Implement the application use case that, given a user/session identifier and the confirmed column mapping, reads the unique category values via `CategoryReaderPort`, builds a `CategoryVocabulary`, and returns a presenter-friendly response. If no values are found, it loads the default category set and marks the source as `default`. The response must include the category list and a prompt asking the user to confirm, add, remove, or rename categories.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] Use case accepts user/session identifier and confirmed column mapping.
  - [x] On detected categories, returns the list with state `detected`/`confirming`.
  - [x] On empty column, returns the default set with state `default`/`confirming`.
  - [x] Persists the initial vocabulary state via the repository port so subsequent messages can resume.
  - [x] Contains all business logic; it does not depend on Telegram or spreadsheet internals.

- **Technical dependencies (block the start):** T-4.07-02, T-4.07-03
- **Delivery dependencies (block the merge):** T-4.07-06, T-4.07-07, T-4.07-09

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** This use case establishes the Clean Architecture boundary: the route handler only deserializes input and delegates here; all decisions (empty-column defaults, state transitions) belong to the use case; the use case communicates through output ports only.
