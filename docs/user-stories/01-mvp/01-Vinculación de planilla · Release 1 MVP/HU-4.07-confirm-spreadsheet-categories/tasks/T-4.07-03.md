### Task T-4.07-03: Implement category vocabulary repository and schema

- **Description:** Define the Drizzle schema for storing category vocabularies and implement the repository that persists and retrieves them. The schema must link categories to a user and their spreadsheet, supporting CRUD operations. Generate a migration using `pnpm db:generate` and ensure it is applied locally.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] Drizzle schema tables for `categoryVocabularies` and `categories` are created under `src/infrastructure/db/schema/`.
  - [ ] Repository implements the `ICategoryVocabularyRepository` port with save, findByUserId, and update methods.
  - [ ] Foreign keys declare explicit `onDelete` behavior.
  - [ ] Migration is generated, applied, and reflected in `docs/architecture/data-model.md`.
  - [ ] Repository tests use an in-memory or test-database instance.

- **Technical dependencies (block the start):** T-4.07-02
- **Delivery dependencies (block the merge):** T-4.07-04

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** Follow the schema-first convention from `AGENTS.md`. Create a port interface first under `src/domain/ports/` and implement it under `src/infrastructure/db/repositories/`. Use transactions when saving vocabulary + categories together. Index the `userId` and `spreadsheetId` columns used in lookups.
