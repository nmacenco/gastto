### Task T-4.07-04: Implement natural-language category edit parser

- **Description:** Implement a domain or application service that parses user messages expressing intent to add, remove, or rename a category. Supported patterns include "falta X" / "add X", "quitar X" / "remove X", and "X se llama Y" / "X is actually Y". The parser returns a structured command (add/remove/rename) with the original and target names, without making any state changes.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] Parser recognizes add, remove, and rename intents in Spanish and English.
  - [x] Returns a typed result (e.g., `AddCategory`, `RemoveCategory`, `RenameCategory`) or `NoMatch`.
  - [x] Preserves the original casing of category names while normalizing surrounding whitespace.
  - [x] Contains no side effects; it is a pure function/service.

- **Technical dependencies (block the start):** T-4.07-01
- **Delivery dependencies (block the merge):** T-4.07-07

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** Consider placing this under `src/application/services/` or `src/domain/services/`. Keep it independent of Telegram message formatting. Unit-test edge cases such as accented characters, multiple spaces, and ambiguous phrasing.
