### Task T-4.02-02: Implement Google Drive file discovery adapter

- **Description:** Implement the `GoogleDriveFileDiscoveryAdapter` in the Infrastructure layer that satisfies `CloudStoragePort` for Google Drive. Use direct `fetch` calls to Google Drive API v3 (no `googleapis` SDK) to list recent spreadsheet files, search by name, and validate that a file is accessible.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] `GoogleDriveFileDiscoveryAdapter` created in `src/infrastructure/adapters/drive/GoogleDriveFileDiscoveryAdapter.ts`.
  - [ ] `listRecentSpreadsheets` queries `https://www.googleapis.com/drive/v3/files` with:
    - `q`: `mimeType` in `'application/vnd.google-apps.spreadsheet', 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet', 'application/vnd.oasis.opendocument.spreadsheet'`.
    - `orderBy`: `modifiedTime desc`.
    - `pageSize`: `5`.
    - `fields`: `files(id,name,mimeType,modifiedTime)`.
  - [ ] `searchSpreadsheets` appends an additional `name contains '{query}'` clause to the `q` parameter.
  - [ ] `validateFileAccess` performs a `files.get` request with the given `fileId`; returns `true` on HTTP 200, `false` on 403/404.
  - [ ] Responses are mapped to the `CloudFile` domain value object.
  - [ ] Errors are mapped to `FileDiscoveryError` or `FileAccessDeniedError`.
  - [ ] Unit tests with mocked `fetch` pass.

- **Technical dependencies (block the start):** T-4.02-01
- **Delivery dependencies (block the merge):** T-4.02-03, T-4.02-06

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** Keep the same lightweight `fetch`-based approach used in `GoogleDriveOAuthAdapter`. Bearer token is passed via `Authorization` header. OneDrive adapter is out of scope for MVP; the use case will return a "coming soon" message for `microsoft` provider.
