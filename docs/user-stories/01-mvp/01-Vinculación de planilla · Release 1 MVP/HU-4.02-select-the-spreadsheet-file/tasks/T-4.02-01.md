### Task T-4.02-01: Define CloudStorage file discovery port and DTOs

- **Description:** Create the `CloudStoragePort` interface in the Domain layer so the Application layer can list, search, and validate spreadsheet files without coupling to Google Drive specifics. Define a `CloudFile` value object that normalizes the response from any provider. Define domain errors for file discovery and access validation failure modes.

- **Architectural layer:** `Domain`

- **Acceptance criteria:**
  - [ ] `CloudFile` value object exists in `src/domain/entities/CloudFile.ts` with fields: `id: string`, `name: string`, `mimeType: string`, `modifiedAt: Date`.
  - [ ] `CloudStoragePort` exists in `src/domain/ports/services.ts` (or a dedicated `src/domain/ports/cloudStorage.ts`) with methods:
    - `listRecentSpreadsheets(accessToken: string, provider: SpreadsheetProvider): Promise<CloudFile[]>`
    - `searchSpreadsheets(accessToken: string, provider: SpreadsheetProvider, query: string): Promise<CloudFile[]>`
    - `validateFileAccess(fileId: string, accessToken: string, provider: SpreadsheetProvider): Promise<boolean>`
  - [ ] Domain errors defined: `FileDiscoveryError`, `FileAccessDeniedError`
  - [ ] All errors extend a common `DomainError` base class or follow the existing project convention (`OAuthDeniedError` pattern).
  - [ ] No external library imports in the Domain layer.

- **Technical dependencies (block the start):** None
- **Delivery dependencies (block the merge):** T-4.02-02, T-4.02-03

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** Follow the existing `SpreadsheetPort` and `OAuthServicePort` patterns in `src/domain/ports/`. Provider type should reuse `SpreadsheetProvider = 'google' | 'microsoft'` from `src/domain/entities/SpreadsheetConfig.ts`. The port accepts an `accessToken` string because token retrieval (via `IOAuthTokenRepository`) is an Application-layer concern.
