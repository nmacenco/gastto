### Task T-4.02-03: Implement HandleSpreadsheetFileSelection use case

- **Description:** Implement the Application use case that orchestrates the entire `ONBOARDING_FILE` state. It retrieves the user's OAuth token, calls the `CloudStoragePort` to list or search files, handles the user's reply (number selection, name search, direct URL, or "none of these"), validates access, persists the selected file in the FSM payload, and transitions to `ONBOARDING_SHEET`.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] `HandleSpreadsheetFileSelection` created in `src/application/use-cases/spreadsheet/HandleSpreadsheetFileSelection.ts`.
  - [ ] Input interface: `{ userId: string; rawMessage: string; externalId: string; channel: 'telegram' | 'whatsapp'; statePayload: Record<string, unknown> | null }`.
  - [ ] Output interface: `{ nextState: FsmState; message: string; payload?: Record<string, unknown> }`.
  - [ ] If `statePayload.fileList` is absent, the use case calls `CloudStoragePort.listRecentSpreadsheets`, formats a numbered list (max 5 items), appends a "None of these / search by name" option, stores the file list in the payload via `TransitionConversationState`, and returns `nextState: 'ONBOARDING_FILE'`.
  - [ ] If the user sends a number matching an item in `statePayload.fileList`, the use case validates the choice, calls `MessagingOutputPort.sendMessage` with a confirmation including the full file name, stores `{ selectedFileId, selectedFileName }` in the payload, and transitions to `ONBOARDING_SHEET`.
  - [ ] If the user sends "none of these" (or equivalent variants), the use case returns a prompt asking for a file name to search.
  - [ ] If `statePayload.step === 'searching'`, the use case calls `CloudStoragePort.searchSpreadsheets` with the user's message as query, presents the refined list, and updates the payload.
  - [ ] If the user pastes a Google Drive or OneDrive URL, the use case extracts the `fileId`, calls `validateFileAccess`, and either selects the file or informs the user of permission issues.
  - [ ] If no compatible files are found, the use case returns a clear message suggesting verification and offering manual name entry.
  - [ ] Unit tests with mocked ports and repository pass.

- **Technical dependencies (block the start):** T-4.02-01, T-4.02-02
- **Delivery dependencies (block the merge):** T-4.02-04, T-4.02-05

- **Estimation:** 2.5 hours

- **Suggested role:** Backend

- **Technical notes:**
  - Clean Architecture boundary: the route handler (Interfaces layer) **only** deserializes, validates, and delegates. This use case contains **all** business logic. The `MessagingOutputPort` and `CloudStoragePort` (Application output ports) keep the use case agnostic of Telegram/WhatsApp and Google Drive.
  - The selected `fileId` and `fileName` are stored in `conversationStates.statePayload` because the `spreadsheet_configs` table requires `sheetName` and `accessVerifiedAt` (not available until HU-4.03 and HU-4.04). The full `SpreadsheetConfig` DB record will be created once all required fields are known.
  - Use the existing `TransitionConversationState` pattern for state changes.
  - Use `onboardingCopies` (T-4.02-05) for all user-facing text.
