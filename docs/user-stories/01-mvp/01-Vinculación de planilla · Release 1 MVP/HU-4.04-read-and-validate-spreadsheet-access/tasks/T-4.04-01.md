### Task T-4.04-01: Define spreadsheet access domain port and value objects

- **Description:** Define the domain-layer interfaces and value objects needed to abstract spreadsheet reading and write-permission checking. Create a driven port interface `ValidateSpreadsheetAccessPort` (or similar) that declares methods for reading a preview (first 10 rows) and checking write permissions. Define value objects such as `SpreadsheetPreview` (containing rows, sheet name, provider) and `SpreadsheetAccessResult` (discriminated union covering: success, read-only, empty-sheet, access-error). All types must be pure domain constructs with no dependency on Google Sheets or Excel Online SDKs.

- **Architectural layer:** `Domain`

- **Acceptance criteria:**
  - [x] Driven port interface `ValidateSpreadsheetAccessPort` is defined under `src/domain/ports/`.
  - [x] Value objects `SpreadsheetPreview` and `SpreadsheetAccessResult` are defined under `src/domain/value-objects/` (or `src/domain/entities/` as appropriate).
  - [x] `SpreadsheetAccessResult` covers all four scenarios: success, read-only, empty-sheet, access-error.
  - [x] No external SDK imports (Google, Microsoft) in domain files.
  - [x] Unit tests verify value object construction and discriminated union shape.

- **Technical dependencies (block the start):** None
- **Delivery dependencies (block the merge):** T-4.04-02, T-4.04-03, T-4.04-04
