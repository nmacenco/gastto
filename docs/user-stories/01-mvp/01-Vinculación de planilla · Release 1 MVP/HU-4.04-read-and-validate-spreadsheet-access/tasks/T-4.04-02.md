### Task T-4.04-02: Implement Google Sheets preview and write-permission adapter

- **Description:** Implement the Google Sheets adapter that fulfills the `ValidateSpreadsheetAccessPort` driven port. The adapter must: (1) read the first 10 rows of the selected sheet via the Google Sheets API, (2) detect if the sheet is empty, (3) verify write permissions by attempting a lightweight write probe or checking the file's capability metadata. Handle network errors and expired/invalid tokens, returning structured `SpreadsheetAccessResult` values. All Google-specific logic must be isolated in this adapter.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] Adapter implements `ValidateSpreadsheetAccessPort` interface.
  - [ ] Reads first 10 rows from Google Sheets API successfully.
  - [ ] Detects empty sheet and returns `empty-sheet` result.
  - [ ] Verifies write permission and returns `read-only` result when lacking write access.
  - [ ] Returns `access-error` result with descriptive error type on network failure or expired token.
  - [ ] No Google-specific types leak into domain or application layers.
  - [ ] Unit tests with mocked Google API client cover all four result variants.

- **Technical dependencies (block the start):** T-4.04-01
- **Delivery dependencies (block the merge):** T-4.04-05

- **Estimation:** 2.5 hours

- **Suggested role:** Backend

- **Technical notes:** Place adapter under `src/infrastructure/adapters/sheets/`. Follow existing adapter patterns in the project. Use the project's Google OAuth token management. Refer to `AGENTS.md` infrastructure adapters section. Mock the Google API client in tests — never call real APIs.
