### Task T-0.02-04: Implement unsupported message handler

- **Description:** Create an Application-layer handler (or secondary use case) invoked by the router when `MessageType` is `UNSUPPORTED`. It must return a friendly response to the user: "For now I only process text messages. Tell me about your expense by typing it." The actual sending of the message is performed via the output port so that this handler remains agnostic of Telegram.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] Handler lives in `src/application/use-cases/` or `src/application/services/`.
  - [ ] Returns the exact copy for unsupported types.
  - [ ] Uses the output port to dispatch the response; no direct Telegram API calls.
  - [ ] Does not throw or log errors for unsupported types.
  - [ ] Unit test verifies the correct message is returned for audio, image, and sticker payloads.

- **Technical dependencies (block the start):** T-0.02-03
- **Delivery dependencies (block the merge):** T-0.02-07

- **Estimation:** 1 hour

- **Suggested role:** Backend

- **Technical notes:** Keep the handler pure from external concerns. The response copy is a public contract; any future change to the wording must be intentional and reviewed.
