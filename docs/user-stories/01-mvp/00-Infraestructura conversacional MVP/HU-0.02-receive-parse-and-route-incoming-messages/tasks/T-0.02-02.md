### Task T-0.02-02: Implement Telegram payload parser

- **Description:** Build an Infrastructure adapter that receives the raw JSON payload from the Telegram webhook and transforms it into the domain `IncomingMessage` value object. The parser must extract `chat_id`, `user_id`, `text`, and `timestamp`, validate their presence and shape, and return a structured result. If the payload does not match the expected Telegram schema, it should return a `MALFORMED` type rather than throwing.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] Parser adapter lives in `src/infrastructure/adapters/telegram/`.
  - [ ] Successfully extracts `chat_id`, `user_id`, `text`, and `timestamp` from a standard Telegram message payload.
  - [ ] Returns a `NormalizedPayload` domain object on success.
  - [ ] Returns a `MALFORMED` result (not an exception) when required fields are missing.
  - [ ] Unit tests cover happy path and missing-field scenarios.

- **Technical dependencies (block the start):** T-0.02-01
- **Delivery dependencies (block the merge):** T-0.02-03, T-0.02-05

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** Keep the adapter thin — it only maps external data to domain objects. All validation rules should be expressible via the domain type constructors. Use `vitest` for tests. Refer to Telegram Bot API docs for Update object shape.
