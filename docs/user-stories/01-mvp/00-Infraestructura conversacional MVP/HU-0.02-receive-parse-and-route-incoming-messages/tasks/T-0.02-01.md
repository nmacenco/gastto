### Task T-0.02-01: Define domain message types and value objects

- **Description:** Create the core domain types that represent an incoming message from any external channel. Define a `MessageType` discriminated union or enum (`TEXT`, `UNSUPPORTED`, `MALFORMED`), an `IncomingMessage` value object containing `chatId`, `userId`, `text`, `timestamp`, and a `NormalizedPayload` contract. These types live in the Domain layer so that Application and Infrastructure remain decoupled from Telegram specifics.

- **Architectural layer:** `Domain`

- **Acceptance criteria:**
  - [x] `MessageType` enum or union is defined in `src/domain/value-objects/`.
  - [x] `IncomingMessage` value object is immutable and validates required fields.
  - [x] `NormalizedPayload` port/interface is defined in `src/domain/ports/`.
  - [x] Types are exported and importable by upper layers without circular dependencies.

- **Technical dependencies (block the start):** None
- **Delivery dependencies (block the merge):** T-0.02-02

- **Estimation:** 1.5 hours

- **Suggested role:** Backend
