### Task T-0.03-05: Add structured logging for all send operations

- **Description:** Integrate structured logging so that every send attempt (success, retry, or permanent failure) produces a log entry containing timestamp, chat_id, message length, and final result. Logs should use `console.error` for failures with a structured object as per the project's observability conventions.

- **Architectural layer:** `Cross-cutting`

- **Acceptance criteria:**
  - [ ] Every call to the messaging adapter produces a log entry.
  - [ ] Log entries include at minimum: timestamp, chat_id, text length, attempt number, and result (success / retry / failure).
  - [ ] Permanent failures (after retries or 4xx) are logged with `console.error` using a structured object.
  - [ ] No stack traces are leaked outside the server logs.
  - [ ] Logging is verified in unit tests via spies/mocks.

- **Technical dependencies (block the start):** T-0.03-03, T-0.03-04
- **Delivery dependencies (block the merge):** None

- **Estimation:** 1 hour

- **Suggested role:** Backend

- **Technical notes:** Follow the observability convention from `AGENTS.md`: `console.error({ endpoint, code, userId? })` for errors. For this adapter, log shape could be: `console.log({ event: 'message_sent', chatId, textLength, attempt, result })` and `console.error({ event: 'message_send_failed', chatId, textLength, errorCode, reason })`.
