### Task T-0.03-02: Implement Telegram HTTP sender adapter

- **Description:** Implement the concrete messaging adapter in the Infrastructure layer that calls the Telegram Bot API `sendMessage` endpoint. This task covers the basic HTTP POST request, response handling, and mapping to the Application layer's output port result type. Do not implement retry or splitting yet; focus on a single, synchronous-by-caller request.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] An adapter class implements the messaging output port defined in T-0.03-01.
  - [ ] The adapter uses the Telegram Bot API token (already configured in HU-0.01) to authenticate requests.
  - [ ] A successful API call returns the mapped `SendResult` with status `success`.
  - [ ] A failed API call (any non-2xx) returns the mapped `SendResult` with status `failure` and a generic error code.
  - [ ] The adapter is registered in the dependency injection / service locator if the project uses one.

- **Technical dependencies (block the start):** T-0.03-01
- **Delivery dependencies (block the merge):** T-0.03-03, T-0.03-04

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** Use the HTTP client already available in the project (e.g., Fastify's `undici` or `fetch`). The Telegram endpoint is `POST https://api.telegram.org/bot<token>/sendMessage` with JSON body `{ chat_id, text }`. Keep the adapter in `src/infrastructure/adapters/telegram/`. Refer to `AGENTS.md` for the adapter conventions.
