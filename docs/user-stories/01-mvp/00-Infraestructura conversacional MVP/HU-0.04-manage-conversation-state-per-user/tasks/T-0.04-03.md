### Task T-0.04-03: Implement corrupted state recovery use case

- **Description:** Create `RecoverCorruptedState` use case in `src/application/use-cases/conversation/`. It receives a `userId` and an observed invalid state string. It validates the state against `FSM_STATES`. If invalid, it logs an anomaly via `IOperationLogRepository`, resets the user state to `IDLE` via `IConversationStateRepository.transition`, and returns a recovery message DTO. The Interfaces layer (worker or route) then sends the recovery message to the user. This encapsulates the corrupted-state business rule in the Application layer.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] Use case detects states not present in `FSM_STATES`.
  - [x] It creates an `operation_logs` entry with `errorType` set to `'CORRUPTED_STATE'`.
  - [x] It transitions the user to `IDLE` with `null` payload.
  - [x] It returns a recovery message payload (not sending the message directly).
  - [x] Output port (`MessagingOutputPort`) remains in the Application layer to keep the use case infrastructure-agnostic.

- **Delivery dependencies (block the merge):** T-0.04-05
