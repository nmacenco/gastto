### Task T-0.04-04: Implement session timeout worker

- **Description:** Create a BullMQ worker in `src/interfaces/workers/` (or a scheduled job) that periodically queries `IConversationStateRepository.findExpired()` and handles interrupted sessions. For each expired state, the worker transitions the state to `IDLE` (or a dedicated `INTERRUPTED` state if added to the FSM) and sends the user a message asking whether they want to continue or start over. The worker runs against the Redis-backed BullMQ queue. Register the worker in the server bootstrap.

- **Architectural layer:** `Interfaces`

- **Acceptance criteria:**
  - [ ] Worker/job queries `findExpired()` at a regular interval (e.g., every 1 minute via BullMQ repeatable job or cron).
  - [ ] For each expired state, it transitions the user to a safe state.
  - [ ] It sends a "Your session expired. Continue or start over?" message via the messaging adapter.
  - [ ] Structured error logging on failures (per `AGENTS.md` Observability rules).
  - [ ] Worker registration does not block server startup on failure.

- **Technical dependencies (block the start):** T-0.04-01
- **Delivery dependencies (block the merge):** T-0.04-06

- **Estimation:** 3 hours

- **Suggested role:** Backend

- **Technical notes:**
  - `expiresAt` field and `findExpired()` are already defined in schema and port.
  - Use BullMQ repeatable jobs or a separate queue with cron semantics.
  - The `message.worker.ts` already uses `bullmq` and `ioredis`; follow the same pattern.
  - Ensure the worker uses the same Redis connection configuration as the other workers.
