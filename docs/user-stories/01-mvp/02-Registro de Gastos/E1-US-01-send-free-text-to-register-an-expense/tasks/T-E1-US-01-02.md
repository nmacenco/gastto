### Task T-E1-US-01-02: Implement heuristic expense-intent classifier

- **Description:** Create an application-level service `ClassifyFreeTextExpenseIntent` that uses the domain `FreeTextIntent` value object to classify incoming text messages. This service provides a clean, injectable interface for `RouteIncomingMessage` to consume. The classifier remains pure — no I/O, no network calls, no channel-specific dependencies — so it can be unit-tested without infrastructure mocks.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] `ClassifyFreeTextExpenseIntent` service exists in `src/application/services/` or alongside conversation use cases.
  - [x] Classifies expense-like messages (e.g., "Pagué el almuerzo, 12 euros", "Almuerzo 12") as `expense-like`.
  - [x] Classifies non-financial messages (e.g., "Hola", "👋") as `non-financial`.
  - [x] Classifies long messages (>500 chars) as `too-long`.
  - [x] Returns a typed result that the caller can switch on.
  - [x] Unit tests cover all four Gherkin scenarios from E1-US-01.
