### Task T-E1-US-01-01: Define free-text message intent value object

- **Description:** Create an immutable value object `FreeTextIntent` in the Domain layer that encapsulates the classification of incoming free-text messages. Define a discriminated union type with three variants: `expense-like`, `non-financial`, and `too-long`. Include a factory method that accepts raw text and returns the appropriate intent using simple heuristics: length check (>500 chars → `too-long`), presence of numeric amounts or currency symbols/words or expense-related keywords → `expense-like`, otherwise → `non-financial`. Keep the value object pure — no dependencies on infrastructure or application services.

- **Architectural layer:** `Domain`

- **Acceptance criteria:**
  - [x] `FreeTextIntent` value object exists in `src/domain/value-objects/` with three intent variants: `expense-like`, `non-financial`, `too-long`.
  - [x] Static factory method accepts raw text and returns the correct intent.
  - [x] Messages over 500 characters are classified as `too-long`.
  - [x] Messages containing numeric values or recognizable expense keywords are classified as `expense-like`.
  - [x] Messages without any financial content are classified as `non-financial`.
  - [x] Unit tests cover all four acceptance scenario patterns from E1-US-01.

- **Technical dependencies (block the start):** None
- **Delivery dependencies (block the merge):** T-E1-US-01-02, T-E1-US-01-04

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:**
  - Existing reference: `src/domain/value-objects/MessageType.ts` for the union type pattern.
  - Threshold for "too long": 500 characters per AC.
  - Heuristic signals: numeric amounts (`\d+`), currency symbols (`$`, `€`, `£`), currency words (`euros`, `dólares`, `pesos`), expense verbs (`pagado`, `gasté`, `compré`, `paid`, `spent`, `ate`, `compró`).
  - Keep heuristics simple and deterministic — refinement happens in later stories.
  - Run tests with `pnpm test`.
