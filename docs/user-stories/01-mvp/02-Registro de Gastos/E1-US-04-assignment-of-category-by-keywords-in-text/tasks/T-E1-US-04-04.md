### Task T-E1-US-04-04: Implement keyword-based category classifier

- **Description:** Implement the application-layer classification use case/service. It must receive the user's message text, load the user's confirmed vocabulary, match keywords, compute a confidence score, detect ambiguity against a configurable threshold, and handle the case where the inferred category is not present in the user's spreadsheet. All business logic lives here; no external service details are allowed.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] The classifier returns a single canonical category with high confidence when one unambiguous keyword dominates.
  - [x] When multiple keywords all map to the same category, confidence is high and the result is not flagged as ambiguous.
  - [x] When keywords map to multiple categories and ambiguity exceeds the configured threshold, the result is flagged as ambiguous and proposes the most likely category.
  - [x] When no keyword matches, the result represents "no category" without blocking the flow.
  - [x] When the inferred category is not in the user's spreadsheet, the classifier delegates to the fallback mapper and marks the result as a fallback.
  - [x] The use case depends only on domain value objects and application ports.

- **Technical dependencies (block the start):** T-E1-US-04-03
- **Delivery dependencies (block the merge):** T-E1-US-04-06, T-E1-US-04-07, T-E1-US-04-08

- **Estimation:** 5 hours

- **Suggested role:** Backend

- **Technical notes:** Implement at `src/application/services/keyword-category-classifier.ts` or as a use case at `src/application/use-cases/classify-expense-category.ts`. Make the confidence threshold configurable via the existing config loader. Use simple tokenization and overlap counting; no ML is required for this story.
