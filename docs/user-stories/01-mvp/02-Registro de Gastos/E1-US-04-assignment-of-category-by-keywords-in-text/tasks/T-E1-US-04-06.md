### Task T-E1-US-04-06: Implement category fallback mapper for unknown categories

- **Description:** Implement an infrastructure/domain helper that, when the classifier infers a category not present in the user's spreadsheet, finds the closest available category in the user's vocabulary. The fallback must be explicit and marked so the summary can flag it for user correction.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [x] A fallback mapper service/adapter exists and is used by the classifier.
  - [x] Given an inferred category and the user's vocabulary, it returns the closest available category or a "no category" result.
  - [x] The returned `ClassificationResult` has `kind = 'fallback'`.
  - [x] If no reasonable close match exists, it returns the "no category" state.
  - [x] The mapping strategy is deterministic and covered by unit tests.

- **Technical dependencies (block the start):** T-E1-US-04-04, T-E1-US-04-05
- **Delivery dependencies (block the merge):** T-E1-US-04-07

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** Start with exact canonical-name matching; if needed, add a simple string-similarity heuristic (e.g., Levenshtein) for common synonyms. Keep the logic isolated in its own module under `src/infrastructure/adapters/` so it can be replaced later with a more sophisticated approach.
