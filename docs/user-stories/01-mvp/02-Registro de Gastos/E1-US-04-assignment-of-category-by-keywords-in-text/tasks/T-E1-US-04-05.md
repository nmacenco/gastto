### Task T-E1-US-04-05: Implement category vocabulary repository adapter

- **Description:** Implement an infrastructure adapter for the `ICategoryVocabularyRepository` output port. It must fetch the user's confirmed category vocabulary produced during the spreadsheet linking process (E4-US-06) and transform it into the domain `CategoryKeywordVocabulary` value object. The implementation must be swappable for tests.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [ ] An adapter class implements `ICategoryVocabularyRepository`.
  - [ ] The adapter fetches vocabulary using the spreadsheet or repository mechanism produced by E4-US-06.
  - [ ] It maps external category names to canonical category identifiers and keywords.
  - [ ] It returns the domain `CategoryKeywordVocabulary` value object.
  - [ ] It handles missing or empty vocabulary gracefully (falls back to base vocabulary).
  - [ ] It is covered by integration-style tests with the external boundary mocked.

- **Technical dependencies (block the start):** T-E1-US-04-03
- **Delivery dependencies (block the merge):** T-E1-US-04-06, T-E1-US-04-07

- **Estimation:** 3 hours

- **Suggested role:** Backend

- **Technical notes:** Place the adapter under `src/infrastructure/adapters/` or `src/infrastructure/db/repositories/` depending on whether E4-US-06 stores vocabulary in the database or a spreadsheet. Consult `docs/architecture/data-model.md` and the existing schema before adding new tables or columns.
