### Task T-E1-US-03-03: Implement amount and currency extraction service

- **Description:** Implement a pure domain/application service in `src/application/services/` that receives raw user text and returns an `AmountCurrencyExtractionResult` (from T-E1-US-03-02). The service must recognize: symbols before the number ($, €, £), ISO codes after the number (EUR, USD, ARS), thousands separators as period or comma, and decimals as period or comma. It should handle ambiguous symbols (e.g., `$`) by returning an `AmbiguousCurrency` failure unless a default currency is provided as an argument.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] Extracts `45.50` and `EUR` from "Pagué 45,50 EUR en el supermercado".
  - [ ] Extracts `1200` from "Gasté $1.200 en el taxi" when a default currency is provided.
  - [ ] Extracts `8500.00` from "Cargué nafta por 8.500,00 pesos".
  - [ ] Returns `AmbiguousCurrency` when only `$` is present and no default currency is supplied.
  - [ ] Returns `AmountNotFound` for messages without a recognizable number.
  - [ ] Returns the detected amount for zero without failing.

- **Technical dependencies (block the start):** T-E1-US-03-02
- **Delivery dependencies (block the merge):** T-E1-US-03-04, T-E1-US-03-07

- **Estimation:** 5 hours

- **Suggested role:** Backend

- **Technical notes:** Keep the service pure (no I/O). Prefer composable regex/heuristics over a single complex expression. Write unit tests alongside this task to cover edge cases; tests are tracked in T-E1-US-03-07. Use `pnpm test` to run Vitest.
