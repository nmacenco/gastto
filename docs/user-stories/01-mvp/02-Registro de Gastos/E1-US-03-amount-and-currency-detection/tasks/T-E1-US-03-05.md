### Task T-E1-US-03-05: Implement clarification request for missing or zero amount

- **Description:** Implement an application use case (or extend the message processing use case) that, when the extraction service returns `AmountNotFound`, `CurrencyNotFound`, or `AmbiguousCurrency`, produces the correct clarification response: "¿Cuánto gastaste?", "¿En qué moneda fue ese gasto?", or the configured default prompt. When the detected amount is zero, generate a confirmation prompt: "¿Querías registrar un gasto de $0?". This use case contains the business decision logic; the Telegram handler only calls it.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] Missing amount triggers the "¿Cuánto gastaste?" clarification.
  - [x] Missing/ambiguous currency triggers the "¿En qué moneda fue ese gasto?" clarification.
  - [x] Zero amount triggers a confirmation prompt before persisting.
  - [x] The route handler does not contain clarification logic.

- **Technical dependencies (block the start):** T-E1-US-03-04
- **Delivery dependencies (block the merge):** T-E1-US-03-06

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** Follow the Clean Architecture boundary: the Interfaces layer (Telegram route handler) only deserializes, validates, and delegates to this use case. All business logic about when to ask for clarification lives in this Application-layer use case. Define an output port (e.g., `ClarificationMessagePort`) so the use case stays agnostic of Telegram or WhatsApp.
