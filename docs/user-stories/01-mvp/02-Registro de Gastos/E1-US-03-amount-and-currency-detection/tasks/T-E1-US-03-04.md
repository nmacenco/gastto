### Task T-E1-US-03-04: Implement default currency fallback via user profile

- **Description:** Implement an application service or use-case step that calls the user profile repository (port) to retrieve the `default_currency` field and passes it to the extraction service. If the repository returns a default currency, the extraction service should use it to resolve ambiguous symbols (e.g., `$`). If no profile/default currency exists, the extraction service must return the ambiguous failure and the conversation must ask for clarification. The use case must remain agnostic of the actual storage implementation through a port.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] A port interface is defined in `src/domain/ports/` for fetching the user's default currency.
  - [x] Use case consults the port before calling the extraction service.
  - [x] Ambiguous symbol `$` is resolved when the user has a default currency.
  - [x] When no default currency exists, the extraction returns `AmbiguousCurrency` without assuming a value.

- **Technical dependencies (block the start):** T-E1-US-03-03
- **Delivery dependencies (block the merge):** T-E1-US-03-05

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** The repository implementation lives in `src/infrastructure/db/repositories/`. Define the port in `src/domain/ports/` and inject it into the application use case via constructor DI. Do not import Drizzle or any storage detail from the application layer.
