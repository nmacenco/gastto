### Task T-E1-US-02-04: Update Telegram webhook to send immediate acknowledgment and enqueue

- **Description:** Update `telegram.webhook.ts` so that, after parsing a valid non-command text payload, it invokes `SendImmediateAcknowledgement` without blocking the HTTP response and immediately enqueues the payload into `incomingMessageQueue`. The route handler remains thin: it only deserializes the body, validates origin, delegates to the use case, and enqueues. All business logic lives in the use case. This guarantees the acknowledgment is emitted within ≤ 1 second even when downstream processing is under load.

- **Architectural layer:** `Interfaces`

- **Acceptance criteria:**
  - [ ] `telegram.webhook.ts` calls `SendImmediateAcknowledgement` for valid text messages.
  - [ ] The acknowledgment send is non-blocking for the HTTP response.
  - [ ] The payload is enqueued to `incomingMessageQueue` before returning HTTP 200.
  - [ ] The route handler does not contain business logic (no copy text, no channel-specific send logic).
  - [ ] Integration tests verify the webhook returns 200 and calls the use case.
  - [ ] Failure to send the ack is logged with a structured `ACK_SEND_FAILED` error and does not crash the request.
