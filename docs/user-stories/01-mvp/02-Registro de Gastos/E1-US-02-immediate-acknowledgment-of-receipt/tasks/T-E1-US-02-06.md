### Task T-E1-US-02-06: Update RouteIncomingMessage to skip duplicate messages

- **Description:** Integrate the idempotency check into the message processing flow. Before `RouteIncomingMessage` enqueues a message into `messageQueue`, call `ProcessedMessageRepository.exists()` and skip processing if the message was already handled. On first-time messages, mark the key as processed at the same time the job is enqueued (or immediately after successful enqueue). This prevents duplicate records when Telegram retries the webhook after a connectivity failure.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] `RouteIncomingMessage` receives `ProcessedMessageRepository` as a dependency.
  - [x] Duplicate messages are detected via `ProcessedMessageRepository.exists()` and are not re-enqueued to `messageQueue`.
  - [x] First-time messages are marked as processed when enqueued.
  - [x] The acknowledgment is still sent for duplicate payloads (the user already received it, but a retry must not break).
  - [x] Unit and integration tests cover duplicate detection and normal flow.

- **Technical dependencies (block the start):** T-E1-US-02-04, T-E1-US-02-05
- **Delivery dependencies (block the merge):** None
