### Task T-E1-US-12-01: Define typed spreadsheet failure categories

- **Description:** Define the domain-level failure contract used by expense saving to distinguish `NETWORK_ERROR`, `AUTH_ERROR`, and `STRUCTURE_ERROR`, while preserving a safe unknown failure category. Extend the existing spreadsheet error boundary or introduce a discriminated result without coupling Application code to Google or Microsoft response formats.

- **Architectural layer:** `Domain`

- **Acceptance criteria:**
  - [ ] The contract represents network, authentication/permission, and spreadsheet-structure failures separately.
  - [ ] The contract exposes whether a failure can be retried without requiring Application code to inspect provider-specific status codes.
  - [ ] Unknown or malformed provider failures map to a safe non-success outcome and cannot be mistaken for a successful save.
  - [ ] Domain tests cover all supported categories and the unknown fallback.

- **Technical dependencies (block the start):** E4 spreadsheet error contract
- **Delivery dependencies (block the merge):** T-E1-US-12-02, T-E1-US-12-03, T-E1-US-12-04, T-E1-US-12-06

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:** Align with `src/domain/errors/SpreadsheetError.ts`, `src/domain/ports/services.ts`, ADR-004, and ADR-006. Keep provider mapping in Infrastructure and keep the Application layer provider-agnostic. Follow `docs/typescript/explicit-undefined-optional-properties.md` when optional metadata is added.
