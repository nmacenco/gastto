### Task T-E1-US-07-02: Add LLM correction-interpretation port and adapter prompts

- **Description:** Extend the `LLMPort` interface in `src/domain/ports/services.ts` with a dedicated correction-interpretation method, `interpretCorrection(rawMessage, currentExtracted, userContext)`. Correction messages are relative to the previously shown summary ("no, fueron 15", "ponlo en transporte", "fue ayer", "no, fueron 15 y es transporte"), so they cannot be re-interpreted with `extractExpense` in isolation — the current extracted expense must be passed as context. Declare a new domain type `ExpenseCorrectionSuggestion` (partial `ExtractedExpense` plus the list of `changedFields` and an `interpretable` flag) in the Domain layer. Implement the new method in all three LLM adapters (`OpenAIAdapter.ts`, `ClaudeAdapter.ts`, `NvidiaAdapter.ts`) with a prompt that includes the current summary as context and instructs the model to return the changed fields only, or nothing when the message is unrelated to any field.

- **Architectural layer:** `Infrastructure`

- **Acceptance criteria:**
  - [x] `LLMPort` exposes `interpretCorrection(rawMessage: string, currentExtracted: ExtractedExpense, userContext: UserContext): Promise<ExpenseCorrectionSuggestion>`
  - [x] `ExpenseCorrectionSuggestion` type exists in the Domain layer with `interpretable: boolean`, `changedFields: ('monto' | 'moneda' | 'categoria' | 'fecha')[]`, and nullable `monto` / `moneda` / `categoriaRaw` / `fechaRaw`
  - [x] OpenAIAdapter, ClaudeAdapter, and NvidiaAdapter implement the method and include the current summary as prompt context
  - [x] A message unrelated to any field resolves to `interpretable: false` with no field changes
  - [x] A multi-field correction ("no, fueron 15 y es transporte") resolves both fields in a single response
  - [x] Adapter unit tests verify prompt construction and response mapping for the three adapters
  - [x] The interpretation engine from E1-US-03/E1-US-04 remains untouched and reusable

- **Technical dependencies (block the start):** T-E1-US-07-01
- **Delivery dependencies (block the merge):** T-E1-US-07-03

- **Estimation:** 4 hours

- **Suggested role:** Backend

- **Technical notes:** `LLMPort` lives in `src/domain/ports/services.ts` (ADR-002). `ExtractedExpense` is defined in `src/domain/entities/ExpenseRecord.ts` (`monto`, `moneda`, `categoriaRaw`, `fechaRaw`, `medioPago`, `confianzaCategoria`). Use strict JSON response schemas consistent with what `extractExpense` already expects in the existing adapters. Keep the deterministic `ExtractAmountCurrency` fallback (`src/application/services/ExtractAmountCurrency`) available for the amount case if the model misses it.
