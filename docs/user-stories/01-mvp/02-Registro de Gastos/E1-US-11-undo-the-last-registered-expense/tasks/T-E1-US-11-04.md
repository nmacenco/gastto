### Task T-E1-US-11-04: Orchestrate last-expense undo

- **Description:** Implement the Application use case that retrieves only the latest undoable expense, decides whether an immediate deletion is safe or explicit confirmation is required after intervening user activity, invokes the spreadsheet deletion output port, then atomically persists the local soft delete and audit event after confirmed deletion. Return presentation-ready typed outcomes for deletion, confirmation, not-found, and failure cases.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] Recognized immediate undo deletes only the latest expense and returns its concept and amount for confirmation.
  - [x] An undo request after intervening user activity returns the latest expense and its saved time as `confirmation_required`, without deleting anything.
  - [x] A confirmation deletes only the previously offered latest record; multiple-record and repeated-undo flows are not introduced.
  - [x] If no undoable record exists, the use case returns `not_found` without calling the spreadsheet deletion port.
  - [x] If the provider rejects deletion, the use case returns `deletion_failed`, leaves the local record active, and records no successful deletion audit event.

- **Technical dependencies (block the start):** T-E1-US-11-01, T-E1-US-11-02, T-E1-US-11-03; E1-US-10
- **Delivery dependencies (block the merge):** T-E1-US-11-05, T-E1-US-11-06

- **Estimation:** 3.5 hours

- **Suggested role:** Backend

- **Technical notes:** The external-trigger handler must only deserialize, validate, and delegate. This use case contains all business logic and uses output ports for spreadsheet and messaging integrations, keeping it independent of chat and spreadsheet providers. Enforce this boundary in code review.
