### Task T-E1-US-11-01: Define undo operation contracts

- **Description:** Define the Application-layer input, discriminated outcomes, and output-port contracts for undoing one saved expense. The contracts must carry the saved expense reference (`spreadsheetId`, `sheetName`, and row reference when available), the displayed concept/amount/currency, and typed deletion failures. Include a confirmation-pending outcome so that a request requiring explicit confirmation cannot delete a record before the user confirms.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] The undo use case accepts the internal user identifier and a normalized action (`request` or `confirm`).
  - [ ] Typed outcomes distinguish `deleted`, `confirmation_required`, `not_found`, and `deletion_failed` without exposing provider errors to chat callers.
  - [ ] The spreadsheet-deletion and chat-delivery contracts are output ports owned by Application, with no Google, Microsoft, Telegram, or WhatsApp types.
  - [ ] The contracts model only one latest expense and do not introduce batch or repeated-undo behavior.

- **Technical dependencies (block the start):** E1-US-10 saved-expense reference contract; E4 spreadsheet deletion capability
- **Delivery dependencies (block the merge):** T-E1-US-11-02, T-E1-US-11-03, T-E1-US-11-04

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** Follow the existing save-location result convention from E1-US-10 and the project's exact optional-property TypeScript conventions. Keep all external integrations behind Application output ports.
