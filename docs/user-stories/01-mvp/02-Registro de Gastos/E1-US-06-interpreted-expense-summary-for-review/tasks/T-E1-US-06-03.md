### Task T-E1-US-06-03: Implement high-amount detection and warning

- **Description:** Add high-amount detection logic to the expense summary flow. The use case must compare the detected amount against the user's historical average (if available). If the amount exceeds 10× the average, the summary must include a warning flag. The presenter must expose an explicit confirmation requirement — the save action is blocked until the user explicitly confirms the high amount.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] High-amount detection logic compares against historical average from the expense repository.
  - [ ] Threshold of 10× the average is configurable.
  - [ ] When no historical data exists, no warning is shown (pass-through).
  - [ ] Summary includes an `isHighAmount` flag and a `requiresExplicitConfirmation` flag.
  - [ ] Presenter is called with the warning state so it can render the ⚠️ indicator.

- **Technical dependencies (block the start):** T-E1-US-06-02
- **Delivery dependencies (block the merge):** T-E1-US-06-05

- **Estimation:** 1 hour

- **Suggested role:** Backend

- **Technical notes:** Inject the expense repository (port interface) to query historical data. Use a simple average query — avoid over-engineering. The 10× multiplier should be a configurable constant.
