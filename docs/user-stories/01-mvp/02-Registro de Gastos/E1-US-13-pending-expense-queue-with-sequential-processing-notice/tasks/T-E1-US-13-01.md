### Task T-E1-US-13-01: Model queued expense state

- **Description:** Define the queue item and queue-state contracts in the Domain layer: immutable raw message, received timestamp, channel/message identity needed for idempotency, FIFO ordering, and a maximum of two pending items. Extend the conversation-state payload contract without adding an `EXPENSE_QUEUE_ACTIVE` FSM state, following the story's preferred separate-queue design.

- **Architectural layer:** `Domain`

- **Acceptance criteria:**
  - [ ] A typed queue item contains only the data required to restart normal expense processing.
  - [ ] Queue operations preserve FIFO order and reject a third pending item deterministically.
  - [ ] The active FSM state and its payload remain independently representable from the pending queue.
  - [ ] Unit tests cover empty, enqueue, dequeue, full-queue, and serialization/deserialization cases.

- **Technical dependencies (block the start):** None
- **Delivery dependencies (block the merge):** T-E1-US-13-02, T-E1-US-13-03

- **Estimation:** 3 hours

- **Suggested role:** Backend

- **Technical notes:** Follow `docs/architecture/fsm-states.md` and ADR-003. Do not encode provider-specific webhook or messaging details in domain contracts.
