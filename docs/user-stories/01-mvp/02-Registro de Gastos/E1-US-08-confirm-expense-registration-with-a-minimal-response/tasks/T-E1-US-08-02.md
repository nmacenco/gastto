### Task T-E1-US-08-02: Implement application-level expense review reply resolution

- **Description:** Create `ResolveExpenseReviewReplyUseCase` under `src/application/use-cases/expense/` to resolve a text reply received while the user is in `EXPENSE_REVIEW`. The use case must apply the precedence rules: a valid minimal confirmation delegates to the existing confirmation/save action described by E1-US-10; a cancellation preserves the existing cancellation behavior; a message containing a partial correction delegates to the E1-US-07 correction use case with the current review payload; and an uninterpretable message returns or sends the orientation copy without mutating the review state. Reuse existing ports and use cases rather than duplicating spreadsheet persistence or correction logic.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] A valid standard or regional confirmation starts the existing save process and does not request another confirmation.
  - [x] A mixed confirmation/correction message is routed to `CorrectExpenseUseCase` and never to the save action; only the corrected field is changed by the existing correction flow.
  - [x] An uninterpretable message produces `¿Confirmamos el registro tal como está, lo corregimos o lo cancelamos?` and leaves the pending payload and FSM state unchanged.
  - [x] Existing cancellation and callback-action behavior is not regressed.
  - [x] Unit tests cover confirmation, partial correction, and uninterpretable reply outcomes.
  - [x] The use case depends on application/domain ports and use cases only; it contains all business logic and has no Telegram, WhatsApp, worker, or adapter dependency.

- **Technical dependencies (block the start):** T-E1-US-08-01, E1-US-06, E1-US-07, E1-US-10 save contract
- **Delivery dependencies (block the merge):** T-E1-US-08-03, T-E1-US-08-04

- **Estimation:** 2.5 hours

- **Suggested role:** Backend
