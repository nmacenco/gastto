### Task T-E1-US-08-01: Define and test the fixed confirmation vocabulary

- **Description:** Extend the application-layer confirmation intent vocabulary in `src/application/utils/intents.ts` with the standard terms from the user story and a deliberately curated set of regional Spanish variants covering Spain, Argentina, Mexico, and Chile. Normalize case, surrounding whitespace, and accents consistently while preserving word boundaries so a partial word or a mixed confirmation/correction sentence is not classified as a standalone confirmation.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [x] `sí`, `si`, `ok`, `dale`, `confirmo`, `correcto`, `listo`, and `va` are recognized as confirmations.
  - [x] `bárbaro`, `okey`, `perfecto`, `yep`, `sip`, plus documented Spain, Argentina, Mexico, and Chile variants are recognized as confirmations.
  - [x] Matching is case-insensitive and tolerant of surrounding whitespace and the supported accent variants.
  - [x] Mixed text such as `comida sí, pero el monto no` and partial words such as `daleeee` are not classified as standalone confirmations.
  - [x] Unit tests document the complete vocabulary and the false-positive boundaries.

- **Technical dependencies (block the start):** E1-US-06, E1-US-07
- **Delivery dependencies (block the merge):** T-E1-US-08-02

- **Estimation:** 1.5 hours

- **Suggested role:** Backend

- **Technical notes:** Keep the vocabulary fixed and reviewable in source control; do not delegate this classification to an LLM. Follow the existing `isConfirmIntent` and `intents.spec.ts` patterns. The external message boundary remains outside this utility: the Interfaces worker only deserializes and validates input, while application use cases own business decisions.
