### Task T-E1-US-04-03: Create output port and adapter for user's spreadsheet vocabulary

- **Description:** Define an output port `CategoryVocabularyPort` in the Application layer that abstracts how the user's spreadsheet category vocabulary is retrieved. The port declares a method `getUserVocabulary(userId: string): Promise<CategoryVocabulary>` that returns the user's confirmed category vocabulary from their linked spreadsheet (sourced from E4-US-06). Create an Infrastructure adapter `SpreadsheetCategoryVocabularyAdapter` that implements this port by querying the user's spreadsheet vocabulary (from the database or spreadsheet API). Add a mapping layer that takes the classifier's inferred category and maps it to the closest available category in the user's vocabulary — if the inferred category exists as-is, use it; if not, find the nearest match by keyword overlap or fall back to "Sin categoría".

- **Architectural layer:** `Application` (port), `Infrastructure` (adapter)

- **Acceptance criteria:**
  - [ ] `CategoryVocabularyPort` interface exists in `src/domain/ports/` or `src/application/ports/` with `getUserVocabulary(userId: string)` method.
  - [ ] `SpreadsheetCategoryVocabularyAdapter` implements the port and retrieves vocabulary from the user's spreadsheet data.
  - [ ] Mapping function `mapToUserVocabulary(inferred: Category, userVocabulary: CategoryVocabulary): Category` exists.
  - [ ] When the inferred category exists in the user's vocabulary, it is returned directly.
  - [ ] When it does not exist, the closest category (by shared keywords) is proposed and the result is flagged for user review.
  - [ ] When no close match exists, returns a null/uncategorized result.

- **Technical dependencies (block the start):** T-E1-US-04-02, E4-US-06 (external — user's spreadsheet vocabulary must be available)
- **Delivery dependencies (block the merge):** T-E1-US-04-04

- **Estimation:** 2 hours

- **Suggested role:** Backend

- **Technical notes:**
  - E4-US-06 is an external dependency — the adapter should work against whatever storage the vocabulary uses after E4-US-06 is implemented.
  - Use the existing repository pattern in `src/infrastructure/db/repositories/` for the adapter.
  - The "closest category" heuristic: compare keyword overlap between the inferred category's aliases and each user category's aliases; the one with the highest Jaccard similarity wins.
