### Task T-E1-US-04-02: Implement keyword-based category classifier service

- **Description:** Create an application service `KeywordCategoryClassifier` that receives raw text and a `CategoryVocabulary` and returns a `CategoryAssignmentResult` with: the best matched `Category`, the `Confidence` level, and a list of alternative categories when ambiguous. The classifier tokenizes the text, matches tokens against keywords in the vocabulary, and scores each category by the number and weight of matched keywords. Define the `CategoryAssignmentResult` as an application DTO with fields: `category` (optional), `confidence`, `alternatives` (array of categories), and `originalText`.

  **Confidence rules:**
  - `high`: keywords from exactly one category matched, no conflict.
  - `medium`: keywords from multiple categories matched but one category clearly dominates (>2× the score of the next best).
  - `low`: keywords from multiple categories matched with close scores, or only weak/indirect matches.
  - `none`: no keywords matched at all.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] `KeywordCategoryClassifier` class exists as an application service with a `classify(text: string, vocabulary: CategoryVocabulary)` method.
  - [ ] Returns `CategoryAssignmentResult` with correct category, confidence, and alternatives.
  - [ ] Single-category keyword match → `high` confidence and that category.
  - [ ] Multiple keywords all pointing to same category → `high` confidence.
  - [ ] Keywords matching multiple categories with clear winner → `medium` confidence with alternatives listed.
  - [ ] No keywords matched → `none` confidence, no category assigned.
  - [ ] All matching is case-insensitive and normalizes special characters.

- **Technical dependencies (block the start):** T-E1-US-04-01
- **Delivery dependencies (block the merge):** T-E1-US-04-03

- **Estimation:** 2.5 hours

- **Suggested role:** Backend

- **Technical notes:**
  - Keep the service pure — no IO, no external calls. It receives all data as parameters.
  - Tokenization: split on whitespace and common punctuation, lowercase.
  - Score calculation: each matched keyword contributes +1 to its category. Alternative categories are those with score > 0 but below the winner.
  - Reference `src/application/services/` for service directory and injection pattern.
