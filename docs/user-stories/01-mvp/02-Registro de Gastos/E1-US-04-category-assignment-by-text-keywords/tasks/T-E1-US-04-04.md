### Task T-E1-US-04-04: Wire category assignment into the expense interpretation flow

- **Description:** Update the expense interpretation use case (from E1-US-03) to invoke the `KeywordCategoryClassifier` after the amount and currency are detected. The use case should: (1) retrieve the user's category vocabulary via `CategoryVocabularyPort`, (2) pass the original message text and vocabulary to the classifier, (3) attach the `CategoryAssignmentResult` to the expense interpretation DTO that flows into the summary. Ensure the category field is presented to the user for confirmation in the summary step. If confidence is `low` or `none`, the category field must be shown as empty/pending with a prompt for the user to fill it — this must NOT block the flow (the user can confirm without a category).

  **Clean Architecture boundary enforcement:** The use case (Application layer) contains all business logic — the classifier call, confidence evaluation, and vocabulary retrieval orchestration. The route handler (Interfaces layer) only deserializes and delegates. An output port keeps the use case agnostic of how results are delivered.

- **Architectural layer:** `Application` (use case), `Interfaces` (route updates if needed)
