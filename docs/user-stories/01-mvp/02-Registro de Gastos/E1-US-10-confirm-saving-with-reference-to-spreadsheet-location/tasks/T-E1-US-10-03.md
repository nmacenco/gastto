### Task T-E1-US-10-03: Orchestrate successful save confirmation

- **Description:** Extend the expense-registration Application use case triggered after E1-US-08 confirmation. After a confirmed write, build the successful confirmation from the expense data and save-location metadata; include sheet and row when available, or only the sheet when the row is unavailable. Delegate message delivery through an Application output port.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] A confirmed save produces a confirmation containing concept, amount, currency, sheet name, and row number when present.
  - [ ] A confirmed save without a row number produces a confirmation containing the sheet name and no row reference or error.
  - [ ] A failed save does not invoke the successful-confirmation output port and follows the E1-US-12 alternative flow.

- **Technical dependencies (block the start):** T-E1-US-10-01, T-E1-US-10-02, E1-US-08, E1-US-12
- **Delivery dependencies (block the merge):** T-E1-US-10-04, T-E1-US-10-05

- **Estimation:** 2.5 hours

- **Suggested role:** Backend

- **Technical notes:** All business rules stay in the use case. The external-trigger handler must only deserialize, validate, and delegate; the use case communicates through output ports and stays agnostic of chat and spreadsheet providers. Enforce this boundary in code review.
