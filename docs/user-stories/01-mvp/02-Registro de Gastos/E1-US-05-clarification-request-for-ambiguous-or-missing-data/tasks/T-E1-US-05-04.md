### Task T-E1-US-05-04: Handle interruption — new expense during clarification

- **Description:** Implement the interruption scenario: when the user sends a new expense message (that looks like a fresh expense, not an answer to the clarification question) while in `EXPENSE_CLARIFYING` state, the system must discard the previous flow without saving it, process the new message as a fresh registration, and notify the user that the previous registration attempt was cancelled. Currently, any text message in `EXPENSE_CLARIFYING` state is routed to `handleClarification()`. Modify the routing logic to detect when the user's message is not a plausible answer to the current clarification question (e.g., it contains an amount and/or currency independent of the question asked), cancel the previous flow by transitioning to `IDLE`, and then re-process the message as a new expense.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] When user is in `EXPENSE_CLARIFYING` for a missing amount and sends a message containing a complete expense (e.g., "Pagué 30 euros por el café"), the previous flow is discarded and the new message is processed as a fresh expense
  - [ ] The user receives a brief notification that the previous registration was cancelled
  - [ ] When the user's message is a plausible answer to the clarification question (e.g., "30 euros"), it continues to be handled by `handleClarification()`
  - [ ] Heuristic to distinguish "new expense" vs "clarification answer" is documented and tested
  - [ ] The state transition follows: `EXPENSE_CLARIFYING` → `IDLE` → `EXPENSE_RECEIVING` (or directly to the result of processing the new message)

- **Technical dependencies (block the start):** T-E1-US-05-03
- **Delivery dependencies (block the merge):** T-E1-US-05-06, T-E1-US-05-07

- **Estimation:** 3 hours

- **Suggested role:** Backend

- **Technical notes:** Modify the `EXPENSE_CLARIFYING` case in `routeByState()` at `message.worker.ts:183` or inside `handleClarification()` at line 701. The heuristic to distinguish a new expense could be: if the message contains both an amount-like token and a currency-like token while the clarification was about a single missing field, treat it as a new expense. Alternatively, use a simple heuristic: if the message length is > 50 chars or matches an expense pattern, assume new expense. The cancellation notification copy is defined in task T-E1-US-05-06.
