### Task T-E1-US-05-05: Handle invalid clarification response with reformulation

- **Description:** Implement the scenario where the user responds to a clarification question with an invalid value (e.g., "no sé" when asked "¿En qué moneda fue ese gasto?"). The system must detect such responses and reformulate the question with concrete options based on the user's context: previously used currencies from the user's expense history, the default currency from the user profile, or a list of common currencies. This requires detecting non-answer patterns (similar to the existing "no sé" detection in `HandleSheetSelection.ts`) and generating a context-aware reformulation message.

- **Architectural layer:** `Application`

- **Acceptance criteria:**
  - [ ] When user responds "no sé" or similar non-answer to a clarification question, the system detects it as invalid
  - [ ] A reformulated message is sent with concrete options (e.g., "¿El gasto fue en pesos argentinos (ARS), euros (EUR) o dólares (USD)?")
  - [ ] The reformulation uses the user's default currency and/or previously used currencies from their expense history
  - [ ] When no history is available, falls back to a reasonable default list based on the user's locale
  - [ ] The clarification state payload is preserved (the flow is not interrupted)
  - [ ] Unit tests cover invalid response detection and reformulation message generation

- **Technical dependencies (block the start):** T-E1-US-05-03
- **Delivery dependencies (block the merge):** T-E1-US-05-06, T-E1-US-05-07

- **Estimation:** 2 hours

- **Suggested role:** Backend

The existing "no sé" detection in `HandleSheetSelection.ts:59-78` can be extracted or reused. The user profile port (`IUserProfilePort`) should provide the default currency.
