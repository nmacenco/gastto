### Task T-E1-US-05-07: Wire clarification flow into Telegram pipeline

- **Description:** The clarification flow is already wired into the Telegram pipeline via the BullMQ message worker: `routeByState()` at `message.worker.ts:137` routes `IDLE`/`EXPENSE_RECEIVING` states to `RegisterExpense.interpret()` which returns `needs_clarification`, and `EXPENSE_CLARIFYING` state to `handleClarification()`. This task verifies the end-to-end integration: the route handler (Interfaces layer) only deserializes the Telegram webhook payload and delegates to the application use case via the worker, with all business logic in the Application layer. Verify that the `EXPENSE_CLARIFYING` → `IDLE` transition for interruption (from T-E1-US-05-04) and the reformulation response (from T-E1-US-05-05) integrate correctly through the worker pipeline.

- **Architectural layer:** `Interfaces`

- **Acceptance criteria:**
  - [ ] The Telegram webhook endpoint (`/webhook/telegram`) correctly delegates message processing to the worker without containing any clarification business logic
  - [ ] The `EXPENSE_CLARIFYING` state is routed to `handleClarification()` in the worker (already working)
  - [ ] The interruption flow (T-E1-US-05-04) correctly transitions state from `EXPENSE_CLARIFYING` through `IDLE` to expense re-processing via the worker
  - [ ] The reformulation response (T-E1-US-05-05) is sent through the `MessagingOutputPort` without blocking the worker
  - [ ] Clean Architecture boundary is maintained: no business logic leaks into the Fastify handler

- **Technical dependencies (block the start):** T-E1-US-05-04, T-E1-US-05-05, T-E1-US-05-06
- **Delivery dependencies (block the merge):** T-E1-US-05-08

- **Estimation:** 3 hours

- **Suggested role:** Backend

- **Technical notes:** The Fastify route is at `src/interfaces/http/routes/webhook/telegram.ts`. The worker is at `src/interfaces/workers/message.worker.ts`. The `MessagingOutputPort` implementations are in `src/infrastructure/adapters/telegram/TelegramMessengerAdapter.ts`. Refer to `docs/adr/adr.md` (ADR-005 for async pipeline, ADR-011 for webhook design).
